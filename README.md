# 纪元 EPOCH · 世界历史地球仪

基于 Next.js App Router、React、Three.js 和本地 SQLite 的历史探索应用。从 1800 年 1 月浏览到启动当日（Asia/Shanghai），支持全球月度视野与国家历史档案。

## 本地启动

需要 **Node.js 22.13 或更新版本**，建议 Node.js 22 LTS。

```bash
npm ci
npm run data:verify
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。首次访问会从项目附带的压缩快照恢复 `data/history.sqlite`，无需先等待网络抓取。服务启动后，后台自动补齐新月份并刷新当前年份和月份。断网仍可查询已有历史。

生产模式：

```bash
npm run build
npm start
```

## 如何使用

- **全球视野**：在底部选择年月，或使用上个月、下个月按钮，查看当月各国要闻。可一键回到当下，也可以切换到「全球精选」，按重要性浏览较少的全球代表事件。
- **国家历史**：点击地球上的国家、常驻国家标签，或在国家筛选器中选择国家，默认展示该国全部历史。使用起止月份筛选范围；选择底部年月则切换到该国单月事件。
- **搜索**：顶部输入国家名称会出现国家入口，同时支持事件、人物和其他关键词搜索。按 `/` 聚焦搜索框，左右方向键切换月份。
- **历史版图**：所选月份驱动 14 个历史疆界重建快照切换。点击区域可查看历史政体、所属关系及快照来源；支持切换当代地图。拖动旋转、滚轮缩放，并提供自动旋转和视角重置。
- **3D／2D 地图**：点击地球国家后展开真正的平面地图并定位到该国，可拖动平移、缩放及点选国家和事件。地图上方可随时切换 3D 地球或 2D 地图，国家、时间筛选和主题保持同步，两种视图均使用随项目分发的本地疆界数据。
- **事件详情**：点击事件列表或地球标记，查看日期、摘要、涉及国家、出处，以及可用的历史照片与署名。
- **同步状态**：左下角数据库入口显示存储规模、覆盖和同步状态，可手动重新检查。手机窄屏在页面下方查看事件列表。
- **白天／黑夜主题**：右上角太阳／月亮按钮切换浅色与深色界面，默认白天。主题偏好以 Cookie 保存，刷新和重新访问会直接使用上次选择；切换时保留当前国家、时间、搜索和地球视角。

## 多语言与中文阅读

右上角可切换 **简体中文 / English**，记住语言偏好，并保留当前国家、年月、时间范围、搜索和主题。国家、日期、地球标签及页面提示随语言切换。

中文史料使用 OpenCC 转为简体显示；缺少当前语言的事件按需翻译。原文不会被改写，详情中可展开原文，机器译文标记来源。译文写入独立 SQLite 表，并按原文内容哈希校验，原文变化后旧译文不会被当作新译文或参与搜索。

默认使用免密钥的 MyMemory API，仅将公开历史摘要发送给服务商。其[官方免费匿名额度](https://mymemory.translated.net/doc/usagelimits.php)为每天 5,000 字符；不适合一次翻译全部历史档案。已缓存的阅读不请求外部翻译，也不消耗服务额度。额度、网络或服务异常时保留原文并显示状态，不伪造译文。界面语言切换与本地历史查询本身没有每日额度。

可在 `.env.local` 配置 `HISTORY_TRANSLATION_PROVIDER=google` 和 `GOOGLE_TRANSLATE_API_KEY` 使用 Google Cloud Translation，或配置 `libretranslate` 和服务地址。计费与额度由提供商决定。`off` 可关闭新的在线翻译，已有缓存仍可阅读。服务端有请求去重、并发限制、超时和失败冷却；列表先展示已有内容，后台完成后自动更新。

```bash
npm run translate -- --month=1969-07 --locale=zh-CN --limit=15
npm run translate -- --month=1969-07 --locale=en --limit=15
npm run data:export           # 不调用翻译 API，把所有本地缓存译文打包，提交 Git 前使用
```

`data/translations.json.gz` 随 Git 分发；首次运行自动导入。浏览时新增的译文先保存在本机数据库，执行 `data:export`、`sync`、`media` 或 `translate` 后才更新 Git 分发快照与校验清单。数据快照已包含首页月份的中英文缓存，其余按需补充。

## 数据与更新

项目附带真实来源的完整历史快照，包括约 **5.3 万条来源记录**和约 **1.3 万条全球月度精选**，覆盖 1800-01 至 2026-10。中文年表优先，缺少中文时保留英文原文。源记录可能对同一事件存在不同语言或不同摘要版本，数量不等于经人工审校的独立事件数。

数据分为两个本地表：`events` 保存全球月度精选，`candidates` 保留更多真实来源事件，供国家历史、关键词搜索及各国月度要闻使用。各国要闻按已识别国家取当月代表事件，不要求其进入全球精选。

通常每月精选五件；重要候选充足时扩展到八件。早期部分月份更少或暂无记录，不强行填充。重要性由明确的关键词、主题、跨国关联、中文可读性和多样性规则评分，属于可修改的探索排序，不是权威结论。

启动同步具有数据库租约锁、限速、超时、429 退避、幂等写入和失败恢复；只导入不晚于本次启动日期的有效日期。历史年份按缺失、失败或缓存过期补查；当前年份每次启动刷新，按上次成功同步时间补查 Current events 月度归档。网络失败会保留原有事件，并在状态面板显示错误。

```bash
npm run sync                  # 检查缺失及到期数据，更新分发快照
npm run sync -- --force       # 重新抓取全部历史；会耗时并受上游限速影响
npm run media                 # 为已知且匹配的历史事件缓存授权照片
npm run db:restore            # 不联网，从分发快照恢复本地数据库（首次启动也会自动恢复）
npm run data:verify           # 校验所有分发数据与资源的 SHA-256
npm run typecheck
npm test
```

可复制 `.env.example` 为 `.env.local`。`HISTORY_AUTO_SYNC=0` 关闭启动时联网；`HISTORY_DB_PATH` 更改数据库位置。命令行脚本读取进程环境变量，可使用 `HISTORY_AUTO_SYNC=0 npm run dev` 的形式传入。

事件快照、补充来源、历史地图、照片、字体、许可与 SHA-256 清单均随 Git 分发，无需 Git LFS。详见 [data/README.md](data/README.md)。本地数据库、抓取缓存不会提交；`data/events.json.gz` 和 `data/supplemental-events.json.gz` 是随代码分发的压缩数据。不要把 SQLite、缓存或压缩快照放进无持久磁盘的 serverless 环境。部署到服务器时，应保留数据库所在磁盘并使用常驻 Node.js 进程。

## 资源与性能

- 14 份历史地图精简坐标、删除冗余属性后 gzip，总计约 **1.23 MB**，只按当前快照加载。
- 历史事件快照 gzip 约 **6.9 MB**；年度 HTML 也以 gzip 缓存，用于后续增量重排。
- 5 张已核实许可的历史照片使用 **WebP、最长边 960 像素、质量 75**，总计约 **363 KB**。下载限制 8 MB，保留作者、原文件页、许可及变换说明。
- 字体本地 WOFF2，约 **58 KB**；地球底图在本地生成，无外部地图服务请求。
- 地球模块延迟加载，事件列表分页，筛选请求可取消；保留地球定位、版图切换、面板过渡、骨架屏与加载进度，支持系统减少动态效果设置。

## 历史地图的精度

快照年份为 **1800、1815、1878、1880、1900、1914、1920、1930、1938、1945、1960、1994、2000、2010**。中间年份使用最近的过往快照，不虚构逐月疆界；例如 1969 年展示 1960 年重建快照，2026 年展示 2010 年快照并明确标注。

这些社区历史重建存在已知年代、名称和边界误差，不是精确的历史主权数据库。国家筛选仍按现代地区索引辅助归类；跨多个现代国家的历史帝国不会被强行归给某个现代国家。事件坐标通常是国家中心的近似位置，无法识别地理位置的记录仍可搜索，不伪造坐标标记。
